### Non-Functional Requirements

Из раздела «Non-Functional Requirements» (подразделы Performance, Security, Reliability, Accessibility, Integration) — нумерация для трассировки:

- NFR-P1: Отзывчивый UI на эталонных проектах v1 при навигации и правках параметров.
- NFR-P2: Пересчёт guillotine с индикатором прогресса; основной поток не блокируется дольше порога из чек-листа приёмки.
- NFR-P3: 3D эталонных корпусов — интерактивный осмотр без заметных фризов на desktop.
- NFR-S1: Нет multi-tenant и обязательной аутентификации в v1; проекты не в общем доступе по умолчанию.
- NFR-S2: Сетевое хранение/синхронизация — TLS; сбор ПДн заказчиков — только при явном scope.
- NFR-S3: Экспорт CSV/PDF без скрытых служебных данных вне схемы v1.
- NFR-R1: Восстановление проектов и профиля после перезапуска без потери полей v1.
- NFR-R2: Сбой пересчёта раскроя не повреждает проект; повтор или откат карты.
- NFR-A1: Читаемость форм и подписей на desktop; контраст карты в PDF для цеха.
- NFR-A2: Полный WCAG AA для маркетинга в v1 не требуется.
- NFR-I1: Внешние интеграции не обязательны в v1.
- NFR-I2: Стабильность полей CSV v1 между минорными релизами; явное версионирование схемы.

**Всего извлечённых NFR-блоков:** 12 формулировок.

### Дополнительные требования и ограничения (не как FR/NFR)

- Критерии успеха, «золотой тест с рулеткой» (±1 мм), чек-лист приёмки.
- MVP scope: типовые корпуса, листы 3500×1750 / 2750×1830, без внешних интеграций.
- Домен: ГОСТы как справочник допусков; ТР ТС 025 — дисклеймер в UI/экспорте; приказ 835н — читаемость карты; 152-ФЗ при облаке.
- Технические ограничения: guillotine-first, grain в раскладке и экспорте, двухслойные размеры и рабочая зона листа.
- Web App: браузерная матрица, desktop-first, Server/Client split, производительность 3D/nesting, SEO не цель v1.
